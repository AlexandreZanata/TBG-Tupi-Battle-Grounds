# P68 Linux candidate: protected sessions and shared desktop presentation

Version: 0.1.0-p68.1. Status: prerelease candidate. Protocol: 30. Schema: 9.
Ruleset: 2 / 3d56156049e626c5. Gameplay/balance numbers are preserved.

Optional native persistence uses the real Linux Secret Service; Windows is
prepared for current-user Credential Manager Local persistence. Access remains
in memory. Browser refresh uses a protected host cookie, coordinated through
Web Locks. Unavailable vaults/cookies use visible temporary sessions. No new
credential is automatically stored in preferences or browser local/session
storage. Existing manual recovery keys and ranked data remain valid.

Passive restoration cannot take over an attached controller. Renewal uses the
current socket, and natural expiry permits the admitted match to finish.
Revocation invalidates all bindings before acknowledgment. Legacy conversion
requires secure persistence/confirmation and explicit backup acknowledgment;
failed or cancelled conversion preserves the recovery key.

The refined Linux presentation is now selected on both desktop targets. The
source gate and zero-tolerance packaged capture contract cover every screen,
loading, model, camera, lighting and animation. Windows binaries, Wine, real
Windows GPU and exact packaged visual acceptance remain pending. A successful
Linux check does not prove Windows or browser behavior.

This candidate is incompatible with the existing protocol-29 production server.
Offline Practice/training remains available; online testing uses a compatible
isolated backend. No production rollout, existing installation replacement,
Wine install or main merge is performed by this delivery.

failures, secure-store behavior, artifact identities and deferred acceptance.
